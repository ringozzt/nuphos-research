github.com/nuphos/nuphos · nuphos.ai · The agent workspace for your team

§0五条硬发现

先给技术读者最承重的五条；细节与出处在后面各节。

1

许可证是真 Apache-2.0，「Other」不是藏条款的证据

根目录 LICENSE 逐字核对为标准 Apache-2.0 全文，无 BSL/ELv2/Commons Clause 类文件；TRADEMARK.md 明说「代码是 Apache-2.0，名字不是」。真正不开的在仓库之外：Android 客户端、托管 runtime 的置备/备份/运维工具、多团队单实例、Google 登录——标准 open-core 形态。「Other」的确切成因官方未说明；「多许可证成分导致许可证探测无法自动归类」是基于文件证据的推断（§4）。

2

真正的技术赌注：把 ACP 从本地 stdio 改造成网络协议

ACP 本是 Zed/JetBrains 为「编辑器 ↔ 本地 agent 子进程」设计的协议。Nuphos 经 OpenAB 网关把它变成 WebSocket 上的远程会话总线（ws(s)://<host>:8080/acp），后端对长寿命 runtime 容器打开 ACP 会话、流式转发——适配器还要打补丁并以 SHA-256 钉住上游产物，上游一升级构建就失败。

3

「仓库 10 天」≠「产品 10 天」：前身叫 Atlas

托管产品 2026 年夏已以「AI 原生 DevOps 工作区」面世（Product Hunt 2026-08-14 上线、EveryDev 8 月收录）；前身仓库 zeabur/atlas 自述为其源码，后端提示词至今叫 atlas-agent-system.md、环境变量仍是 ATLAS_*。2026-10-01 只是开源化 + 重新定位的时点。

4

与 paperclip 是品类之别，不是功能之争

paperclip 做组织图、预算、心跳的「公司治理」，控制面只编排不执行；Nuphos 没有任何雇佣隐喻，做的是多人实时同处一室、共同驾驶一个正在执行的 turn，加上跨机迁移与生产系统 GUI。量级也悬殊：paperclip 约 97.2k stars（二手统计），Nuphos 45。

5

安全模型一句话：共享会话 = 共享权限

runtime README 自己警告——团队密钥是「挡在持有你工作区云凭据的 agent 前面的唯一东西」。能 reply 的人就能以会话作用域凭据驾驶 agent；队友的消息会在机主的本地机器上以机主身份执行命令。AWS assume-role / GCP impersonation 的触达面，是所连账号 CLI 能做的一切。

一个 turn 如何执行（技术核心）

一手后端自己不跑 agent：runtime 是长寿命容器、内含恰一个 agent，后端对 runtime 打开一个 ACP 会话并流式转发对话。镜像分三层：

① OpenAB 网关外部开源项目 openabdev/openab，以 submodule 引入；拥有容器，经网络接受 ACP、监督 agent、agent 重启后保持会话存活。端点 ws(s)://<host>:8080/acp
→
② agent CLI + ACP 适配器Claude 用 @agentclientprotocol/claude-agent-acp（内含 Claude Agent SDK 的 Claude Code CLI）；Codex 用 @openai/codex + @agentclientprotocol/codex-acp
→
③ Nuphos 工具集层git/gh/kubectl 常驻；aws/gcloud/mongosh/psql 等为首次使用才下载钉版的 shim
  • 一手适配器补丁：构建时给适配器打补丁（发布会话状态、桥接 HTTP MCP、Codex 回合内 steering 等），补丁以被改上游产物的 SHA-256 钉住——上游升级会使构建失败，直至人工复核。这是 ACP 赌注的真实维护成本。
  • 一手超出预期的 agent 支持：除 Claude Code / Codex 外，runtime README 还列 Grok Build（xAI）、Google Antigravity、OpenCode——后三者原生说 ACP、无需适配器，只加 acp-shim；Grok/Antigravity 是专有软件不在镜像内，首次使用时从厂商下载。Desktop v0.77.0 亦确认 OpenCode 成为新的 Cloud agent。
  • 一手镜像零凭据：镜像内无任何凭据、无提示词；系统提示词、MCP 服务器、技能与每回合凭据由后端经 ACP 在运行时下发，同一镜像服务所有工作区。容器以 uid/gid 1000、丢弃全部 capabilities 运行；/acp 拒绝无团队/部署密钥的升级请求（401），控制台只存团队密钥的 SHA-256 摘要；/home/node 必须持久卷，内含.claude/.codex 登录态。
  • 一手认证 = 用你自己的订阅：Claude 由 runtime 控制台驱动 claude auth login（粘贴授权码，凭据留在容器卷）；Codex 走设备码登录（隔离的 CODEX_HOME）。Nuphos 不收集 API key，无额外模型费用。

后端与数据栈

  • 一手用户、团队、Google OAuth 与 JWT 会话存于 MongoDB（单节点副本集 rs0，因事务需要）；文件走 S3 兼容对象存储（自托管用 RustFS）；托管版另有 Redis——无 Redis 时 cron、后台队列、审计日志封存被禁用，后端退化为单副本内存模式。
  • 一手后端自带一个内置 agent（系统提示词文件至今名为 atlas-agent-system.md）：通过已加载的 skill 操作团队连接的系统；内置 skill 是 SKILL.md + 脚本（如 asana、gitlab、zeabur），脚本用 NUPHOS_TOKEN 调后端 API 取绑定账号凭据。
  • 一手后端自身的模型调用（会话标题、仪表盘洞察）走 AWS Bedrock；无 Bedrock 密钥时这些功能不可用，但 runtime 上的聊天不受影响。

会话持久与迁移

一手会话状态由后端持有（MongoDB），runtime 只是可替换的执行器——同一会话可在本地机 / 自有远程机 / Nuphos 托管云之间切换并继续，迁移后模型选择器切换为新 agent 的模型列表。本地形态由 CLI nuphos agent 或桌面端提供：首次使用下载本版 runtime 到 ~/.local/share/nuphos/runtime；Claude 为 Nuphos 单独登录一次（与自用终端隔离），Codex 用既有 codex login。

本地 agent 的关键语义（CLI README 明示）：只有机主能在本地机上发起会话；但会话一旦被移上这台机器，团队任何人都能续聊，且他们的消息会以机主身份在这台机器上执行命令。

一手Desktop 细节：electron-updater 每 6 小时检查更新；macOS 构建签名+公证，Windows/Linux 未签名；分屏快捷键 ⌘D / ⌘⇧D，内置浏览器标签页。iOS 为 SwiftUI，已上架 App Store（v0.8.0）；Android 客户端存在但尚未开源。

§3核心产品理念

(a) 会话即「房间」：多人共驾

一手README 开篇即称编程 agent 默认单人、单机、单终端；Nuphos 中会话如同 Notion 页面可邀请——多人对同一 agent 说话、看同一批工具调用、共同转向。会话级权限已产品化（Desktop v0.77.0）：每会话可设「仅受邀者 / 全队可看 / 全队可看可回」，受邀者分 Can reply / Can manage 两级，仅所有者能改权限，Can manage 者可迁移会话与更换凭据。

(b) 会话比机器长寿

一手合上笔记本，回合在远程/云 runtime 继续，手机接续；三种 runtime 形态可互迁（见 §2）。

(c) 团队共享技能与工具

一手授权一次，全队每个 agent 同步获得，不再人人往自己机器上粘 token。runtime 侧由 nuphos-sync-skills 拉取工作区技能包并原子替换；托管 pod 由置备器推送，自托管按会话执行。

(d) 内置团队记忆

一手跨队友、跨 agent、跨会话内置，无需另装 MCP 服务器；桌面端有 Memories 入口，路由为 /teams/<teamId>/agent/memories，以团队为作用域、存于后端（MongoDB 体系）。二手EveryDev 称其为持续积累的团队知识库（服务、环境、工作流、运维历史）。未核实记忆的具体数据表示（自由文本 / 结构化条目 / 向量检索）在公开 README、docs 与官网均未披露。

(e) 触发器：没人说话也能开工

一手cron 定时或 webhook 事件可自主启动一个回合。注意：自托管 Compose 栈无 Redis 时 cron 被禁用（§5）。

(f) 把 agent 放进团队频道

一手一步把同一 agent 放进 Slack / Discord 频道；后续版本做了话题与会话互相绑定、发言者归属显示。二手早期托管版还宣称 Lark 与 iMessage。

(g) 专业 GUI 面板：agent 操作的是账号本身

一手Kubernetes、Grafana（仪表盘/告警/日志/链路）、GitHub、Linear 为一等 GUI，另有 GitLab、AWS（含 ECS）、GCP、Cloudflare、Linode、MongoDB 与 SQL 连接，可分屏多会话同看。关键点：面板不是截图——agent 操作面板背后的账号本身，触达面是所连账号 CLI 能做的一切。

  • 一手云连接（BYOC）：AWS 为跨账号 assume-role，GCP 为服务账号模拟（impersonation）；信任主体是「你的部署」的身份——自托管实例把账号绑到自己，而非 nuphos.ai。
  • 一手官网博客的设计原则：从只读授权起步、会话获得作用域化访问、受保护变更先出计划等人工批准、动作可归因、保留审计。
  • 二手「会话级细粒度 IAM、短期最小权限凭据」等更细说法见 EveryDev 转述，未在仓库文档中逐项找到原文。

§5自托管：三条路径与一条硬约束

一手硬约束：一个部署一个团队——团队是会话、技能、记忆、集成的统一作用域；多团队共存只在托管产品。

  • Zeabur：一键按钮部署数据栈（agent runtime 须在单独项目另行部署；模板 deploy/zeabur/template.yaml）。东家自己的平台，吃自家狗粮。
  • Railway：目前为 CLI 部署指南而非发布的一键模板；但 Desktop v0.77.0 的 agent 设置里已链 Railway 一键模板——两处口径以各自发布日期为准。
  • Docker Compose：deploy/compose 一条命令起全套：MongoDB 8 + RustFS + backend + 一个 Claude Code runtime。

一手自托管可用项：邮箱 OTP 登录对任意后端有效；桌面/iOS 登录页有「Self-hosted? Set API endpoint」入口（或用 NUPHOS_API_URL 启动指定）；runtime 用一次性配对码从控制台连入团队，后端换取团队专属密钥；云账号绑定到自托管实例自身身份。

能力自托管托管 Nuphos Cloud
backend / desktop / iOS / runtime 代码✔ Apache-2.0✔
团队数 / 部署1多
托管 runtime 置备、备份、运维工具✘✔
Google 登录✘（用邮箱 OTP）✔

Compose 栈的已知限制（官方自列）：无 Redis → cron 调度、后台线程队列、审计日志封存禁用；无 Bedrock 密钥 → 后端标题/洞察类模型调用不可用；/admin 未配置；该栈 NODE_ENV=development、端口仅绑 127.0.0.1，明确警告勿公开暴露；托管（managed）agent 在此栈跑不了——它们是后端置备器创建的 Kubernetes Deployment，本地仅能用 OrbStack K8s 测试；runtime 镜像目前仅 amd64，Apple Silicon 下靠模拟运行。

§7竞争格局

产品形态与 Nuphos 的关键差异
paperclip开源（MIT）agent「公司」控制面：组织图、目标层级、工单、预算/成本、审批治理、心跳监控；只编排不执行Nuphos 无组织图/预算/雇佣隐喻，做会话本身：多人实时共驾一个正在执行的 turn、跨机迁移、生产系统 GUI 与云操作。量级悬殊：约 97.2k stars（二手） vs 45
Multica开源托管 agent 平台：把 issue 像分给同事一样分给 agent，agent 自行认领、汇报、阻塞升级，技能可复利沉淀，含 Squads 路由层团队论最接近的竞品，但中心是「看板/issue 异步协作」，不是「同一会话的实时多人房间 + runtime 迁移 + 基础设施 GUI」
Conductor（Melty Labs，YC S24）免费 macOS 应用，并行跑 Claude Code/Codex/Cursor，每 agent 一个隔离 worktree，diff 审查与 PR 流，闭源单人、单机、并行编排；无团队共享会话、无云端续跑、无手机端
Vibe Kanban（BloopAI）开源看板：以 issue 规划、workspace 跑 agent、审查 diff，支持 10+ agent；约 28.3k stars（二手）其公司 Bloop 于 2026-04-10 关停，项目已宣布 sunsetting、转社区维护——「看板编排」路线退潮的标志
Sculptor（Imbue）MIT 开源桌面应用：并行 agent 各自容器/worktree，Pairing Mode 把容器改动实时同步回本地 IDE本地单人、IDE 配对导向；无团队会话与托管 runtime
Terragon（已关停）云端后台 agent 编排：云沙箱并行跑 Claude Code/Codex，BYO 订阅，Slack/GitHub 触发2026-01-16 关停后以 Apache-2.0 快照开源、无维护。与 Nuphos 形态最像的历史玩家，其死亡是该品类商业化难度的直接先例
厂商自有团队/云功能Claude Code 云会话 2026-09-23 转正（云端续跑、多端操控、自托管环境 Beta）；Codex 有云任务（隔离环境并行、团队管理）厂商正在吸收「会话比笔记本长寿」，但都是单厂商围墙：不跨 Claude/Codex 共享技能、记忆与房间，也不操作客户的第三方基础设施 GUI
ACP 生态ACP 由 Zed 于 2025-08 发起、与 JetBrains 共同维护，被喻为 agent 界的 LSP；agent 注册表约 50 个多数采用者是「编辑器 ↔ 本地 agent 子进程（stdio）」；Nuphos 把 ACP 经 OpenAB 变成 WebSocket 网络协议，用作远程 runtime 与后端之间的团队化会话总线——这是它真正的协议赌注

Nuphos 的差异化（综合判断）：① 会话即房间的实时多人共驾，而非看板/组织图式异步分工；② 会话与执行机解耦、三态 runtime 迁移、iOS 接续；③ 工作区同时是生产运维台，连接身份属于客户自己的云账号（BYOC）；④ 跨厂商（ACP 多 agent）+ 团队级技能/记忆共享。四点同时具备者，在已核竞品中没有第二个。

§8批评与风险

年轻与体量

一手开源仅 10 天、45 stars、外部贡献无证据；但产品自 2026 年夏已运营，别把「仓库 10 天」误读为「产品 10 天」。全线版本号 <1.0、约 2 release/天、组件间需兼容矩阵，API 与行为 churn 风险高。内部代号 Atlas 在代码、提示词、环境变量中大量残留，显示改名与转定位仓促。

安全攻击面（最实质的风险）

团队密钥是「挡在持有你工作区云凭据的 agent 前面的唯一东西」。—— runtime README 自述
  • 一手共享会话即共享权限：能 reply 的人就能以该会话的作用域凭据驾驶 agent；Can manage 者还能迁移会话、更换凭据。
  • 一手本地 agent 语义凶险：队友的消息会在机主机器上以机主身份执行命令（CLI README 明示，见 §2）。
  • 一手注入面直达生产：agent 的触达面是所连云账号 CLI 的全部能力；AWS assume-role / GCP impersonation 一旦作用域过宽，Slack/Discord/Linear 等外部内容经 prompt injection 即可触达生产系统；团队共享记忆还带来跨会话的记忆投毒面。
  • 一手缓解多为原则、强制细节披露有限：只读起步、计划审批、作用域会话、审计等缓解项多见于官网博客的原则性表述；自托管 Compose 栈连审计封存都因无 Redis 被禁用。SECURITY.md 的范围划分（团队隔离、沙箱逃逸、桌面 IPC、供应链）本身即承认了这组攻击面的存在。

依赖与先例

  • 一手ACP 适配器依赖：补丁以 SHA-256 钉住上游产物，上游（Claude Agent SDK / Codex）每次升级都要人工复核适配——协议赌注的对价是持续的跟随成本。
  • 二手品类先例不乐观：形态最像的 Terragon 已于 2026-01-16 关停，看板路线的 Vibe Kanban 母公司 Bloop 已关停、项目 sunset——「agent 工作区」这个品类的商业化难度有直接前科。
  • 二手厂商围墙在合拢：Claude Code 云会话已转正、Codex 云任务在推进，厂商自己正在吸收「会话跨机续跑」；Nuphos 的窗口在于跨厂商与团队协作，但窗口不会一直开着。
